# PaperCast AI 四天实施计划

> 版本：V1.0  
> 日期：2026-11-19  
> 目标：在 3–4 天内交付一个可公开演示、可实际操作的 PaperCast MVP。

## 1. 最终目标

评委打开公开链接后，可以完成以下流程：

1. 选择预置论文，或上传一篇文本型 PDF。
2. 生成并播放双角色中文论文播客。
3. 播放过程中按住说话，松开后一次性提交录音。
4. 系统完成 ASR、Qdrant 混合检索和 DeepSeek 回答。
5. 中栏显示文字回答及来源按钮，不生成互动回答语音。
6. 点击来源后，右栏显示论文原文、页码和章节。
7. 用户阅读结束后点击“继续播放”，恢复原播放位置。

## 2. 已确定的产品取舍

### 必须实现

- 双角色播客 TTS。
- 按住说话、松开提交的批量语音输入。
- 文字回答，不做互动 TTS。
- Qdrant Cloud 向量与 BM25 混合检索。
- 中文问题检索英文论文。
- 回答绑定证据 ID。
- 点击来源查看未经改写的论文原文和页码。
- 左、中、右三栏桌面布局。
- 移动端采用抽屉或标签页降级。
- 公网可访问版本及预置样例。

### 本版不做

- 流式 ASR、流式 LLM、WebSocket 问答。
- 互动回答语音。
- 自研向量数据库或本地 BGE-M3。
- Chroma、Milvus 等第二套向量库。
- 扫描 PDF、复杂公式和复杂表格的完整解析保证。
- 用户账号、长期历史、多论文联合问答。
- 严格 3 秒内返回答案。
- 为未来需求提前搭建通用框架。

## 3. 技术架构

```text
React/Vite 前端
├─ PDF 上传与文本型 PDF 解析
├─ 播客播放器与段落导航
├─ MediaRecorder 批量录音
├─ 文字问答
└─ 来源原文面板
        │
        ▼
Qoder Sites 服务端接口
├─ PDF 切片与证据元数据
├─ Qdrant 写入与混合检索
├─ 批量 ASR
├─ DeepSeek 生成简短文字回答
├─ 播客脚本生成
└─ TTS 仅用于播客
        │
        ├─ Qdrant Cloud
        │   ├─ multilingual-e5-small 稠密向量
        │   ├─ qdrant/bm25 稀疏向量
        │   └─ RRF 混合排序
        │
        └─ 对象存储
            ├─ 原始 PDF
            ├─ 播客音频
            └─ manifest.json
```

### 最小依赖原则

- 只使用一个 Qdrant collection。
- 只维护一种证据数据结构。
- 问答只使用一个普通 `POST /api/ask` 请求。
- 长时间的播客生成使用任务 ID 和普通轮询，不引入 WebSocket。
- 优先复用现有 `evidence_pool.json`、播客音频、manifest 和前端播放器。

## 4. Qdrant 设计

### Collection

- 名称：`papercast_evidence`
- Dense vector：`multilingual-e5-small`，384 维。
- Sparse vector：`qdrant/bm25`。
- 融合方式：RRF。
- 检索结果：top-5。

### Payload

```json
{
  "paper_id": "paper_001",
  "evidence_id": "ev_028",
  "page": 4,
  "section": "Architecture",
  "quote": "The original text from the paper...",
  "chunk_index": 28
}
```

### 检索流程

```text
问题文本
→ multilingual-e5-small dense search
→ BM25 sparse search
→ paper_id 元数据过滤
→ RRF 融合排序
→ top-5 原文证据
→ DeepSeek 基于证据回答
```

### 无证据处理

- 检索结果为空或最高分低于实测阈值时，直接返回“论文中没有提供足够信息”。
- DeepSeek 只能引用本次 top-5 中存在的 `evidence_id`。
- 服务端剔除模型返回的非法引用 ID。
- 阈值只能通过评测集确定，不在代码中凭感觉写死。

## 5. 前端三栏布局

```text
┌──────────────────┬────────────────────────────┬──────────────────────┐
│ 左栏：论文导航    │ 中栏：播客与文字问答       │ 右栏：来源原文        │
│                  │                            │                      │
│ 上传/选择论文     │ 播客播放器                 │ Evidence ID          │
│ 学习目标          │ 当前播放段落               │ 页码与章节            │
│ 章节目录          │ 按住说话                   │ 原文 quote            │
│ 播客段落列表      │ transcript                 │                      │
│                  │ 文字回答                   │ 查看 PDF 对应页       │
│                  │ [来源1] [来源2]            │                      │
└──────────────────┴────────────────────────────┴──────────────────────┘
```

### 桌面端

- 左栏固定宽度约 260px。
- 中栏占剩余主要空间。
- 右栏固定宽度约 360px。
- 点击来源只更新右栏，不离开当前播放和问答页面。

### 移动端

- 默认显示中栏。
- 左栏变为“论文目录”抽屉。
- 右栏变为“查看来源”底部抽屉。
- 保留按住说话、来源查看和继续播放三个核心操作。

## 6. API 最小契约

### 健康检查

```http
GET /api/health
```

检查服务端、Qdrant、ASR、LLM 和 TTS 配置是否就绪，不返回密钥。

### 索引论文

```http
POST /api/papers/index
```

输入文本型 PDF 的分页文本或已生成的证据块，返回 `paper_id`、索引状态和证据数量。

### 生成播客

```http
POST /api/podcast/jobs
GET  /api/podcast/jobs/{job_id}
```

任务状态只保留：`queued`、`scripting`、`synthesizing`、`complete`、`failed`。

### 批量问答

```http
POST /api/ask?paper_id=paper_001&segment_id=seg_004&position=66.69
Content-Type: audio/webm
```

响应：

```json
{
  "transcript": "论文采用的核心方法是什么？",
  "answer": "论文采用了可定制的文档转换流水线。",
  "evidence": [
    {
      "evidence_id": "ev_028",
      "page": 4,
      "section": "Architecture",
      "quote": "The original text from the paper...",
      "score": 0.86
    }
  ],
  "resume_segment_id": "seg_004",
  "resume_position_seconds": 66.69,
  "timings": {
    "asr_seconds": 2.8,
    "retrieval_seconds": 0.3,
    "llm_seconds": 1.7,
    "total_seconds": 4.8
  }
}
```

## 7. 四天实施安排

### Day 1：Qdrant 与公网能力验证

工作：

1. 建立 Git 基线，保护当前成果。
2. 创建 Qdrant Cloud 免费集群和 `papercast_evidence` collection。
3. 导入现有 221 条 `evidence_pool.json` 数据。
4. 使用中文问题验证英文原文的 dense、BM25 和 hybrid 检索。
5. 完成最小 `retrieve(question, paper_id)` 服务端函数。
6. 验证 Qoder Sites 服务端能够访问 Qdrant Cloud。
7. 发布最小公网页面，验证手机访问和现有播客播放。

当天交付：

- 公网页面可打开。
- Qdrant 能写入和检索现有证据。
- 至少 10 个基准问题中 8 个能在 top-5 找到正确原文。

止损条件：

- 如果 Qoder Sites 无法稳定访问 Qdrant Cloud，当天切换到 DashVector；不继续排查超过半天。
- 如果 Cloud Inference 不可用，保留 Qdrant，仅把 Embedding 改为百炼文本向量 API。

### Day 2：论文索引与播客主流程

工作：

1. 接入文本型 PDF 上传和分页文本提取。
2. 按页、段落生成证据块，保留 `page` 和 `quote`。
3. 将证据块写入 Qdrant，并绑定 `paper_id`。
4. 复用现有脚本生成和 TTS 能力生成双角色播客。
5. 生成 manifest，绑定每段播客的 `evidence_ids`。
6. 前端显示生成阶段与失败重试。

当天交付：

- 预置论文完整流程稳定运行。
- 至少一篇新的文本型 PDF 能完成索引。
- 播客能够播放、跳转段落并展示对应证据。

降级条件：

- 新 PDF 播客生成若在当天结束前仍不稳定，正式演示保留预置论文；上传功能标为 Beta，不阻塞核心演示。

### Day 3：批量语音问答与三栏证据界面

工作：

1. 将 `/api/ask` 改为 ASR → Qdrant hybrid → DeepSeek 的同步文字问答。
2. 删除互动 TTS 和回答音频等待。
3. 回答限制为 1–3 句、80–150 字。
4. 完成非法引用剔除和无证据拒答。
5. 完成左、中、右三栏布局。
6. 点击来源后在右栏显示原文、页码和章节。
7. 问答时暂停播客，用户点击“继续播放”后恢复。

当天交付：

- 真人按住说话能够返回 transcript、文字答案和来源。
- 点击来源能够看到对应原文。
- 不再等待互动回答音频。
- 桌面端完整三栏流程可演示。

### Day 4：验收、移动端与发布

工作：

1. 完成移动端抽屉布局。
2. 验证 Chrome、Edge、Android 和 iPhone/Safari 的录音格式。
3. 增加上传大小、文件类型、录音大小和超时限制。
4. 增加错误提示、重试按钮和预置样例兜底。
5. 完成检索评测、延迟记录和连续端到端冒烟测试。
6. 固定演示论文、演示问题和演示步骤。
7. 发布最终公网版本。

当天禁止：

- 新增模型、新向量库、新交互模式或视觉主题。
- 重写已经能工作的模块。
- 为低概率边界情况扩张架构。

## 8. 验收标准

### 功能

- 公网链接无需登录即可访问。
- 预置论文播客可播放、暂停和跳转。
- 按住说话、松开提交能够完成一次问答。
- 回答为文字，不生成互动语音。
- 每个事实性回答至少有一个有效来源。
- 点击来源显示正确原文、页码和章节。
- 无证据问题能够拒答。
- 用户可手动恢复原播放位置。

### 检索

评测集至少包含 30 个问题：

- 15 个正常论文问题。
- 5 个同义改写问题。
- 5 个中文问英文原文问题。
- 5 个论文无法回答的问题。

目标：

- 可回答问题 top-5 证据召回率 ≥ 85%。
- 不可回答问题正确拒答率 ≥ 80%。
- Qdrant hybrid 不低于当前关键词检索基线。

### 性能

- ASR：通常 ≤ 4 秒。
- Qdrant 检索：通常 ≤ 1 秒。
- 文字回答总延迟：中位数 ≤ 6 秒，单次尽量 ≤ 10 秒。
- 点击来源后原文显示：≤ 300ms。
- 播客生成：预置目标 ≤ 5 分钟；超时必须显示进度或错误。

### 稳定性

- 连续执行 10 次问答无页面卡死。
- 前端构建通过。
- 关键检索与引用校验测试通过。
- 浏览器控制台无阻塞性错误。
- 服务端不向前端返回 API Key、堆栈或本地路径。

## 9. 风险与唯一降级路线

| 风险 | 处理 |
|---|---|
| Qoder Sites 无法连接 Qdrant Cloud | 当天切换 DashVector，保持接口与 payload 不变 |
| Qdrant 内置 Embedding 不可用 | 使用百炼文本向量 API，向 Qdrant 写入原始向量 |
| 新 PDF 解析质量不稳定 | 正式演示使用预置论文，上传标记为 Beta |
| 播客在线生成过慢 | 预置论文使用已生成音频，新论文显示任务进度 |
| ASR 误识专业词 | 页面显示 transcript，允许用户编辑后重新提交文字问题 |
| 检索相似但不能回答 | 使用分数阈值、引用白名单和无证据拒答 |
| 手机三栏空间不足 | 左右栏改为抽屉，中栏保持主操作 |

## 10. 演示脚本

1. 打开公网链接，选择预置 Docling 论文。
2. 播放播客并跳转到方法段落。
3. 按住说话：“论文采用的核心方法是什么？”
4. 展示 ASR transcript 和文字回答。
5. 点击“来源 1”，右栏展示英文原文和页码。
6. 提问一个论文未提供的问题，展示系统拒答。
7. 点击“继续播放”，恢复原位置。
8. 如上传功能稳定，再上传第二篇文本型 PDF 展示索引过程。

## 11. 完成定义

以下条件全部满足，MVP 即视为完成：

- 公网版本可访问。
- 双角色播客可播放。
- 批量语音输入可用。
- Qdrant 混合检索替代现有纯关键词检索。
- 互动只返回文字答案。
- 三栏证据溯源完整可用。
- 预置样例能够稳定走完整流程。
- 检索、延迟和稳定性达到本计划验收标准。
