## 3. 部署前必办（按优先级）

1. **S1 发布验证**（用户触发）：Qoder IDE 打开 `papercast-site` → 站点发布 → public → 拿链接 → 手机打开验证静态页与播客播放。
2. **S2–S7 平台能力核验**：Python 函数运行时 / 请求超时上限 / 音频存储 / 数据库 / 外部 API 出口（DeepSeek、Qdrant Cloud）。
   ⚠️ 原 `final_recommendation.md`（含 S1–S7 清单）在文件丢失事故中缺失，本清单为重建口径。
3. **后端托管决策**：本地 ASR（faster-whisper）+ 13MB 级音频需要能承载模型的主机；`serve_local.py` 仅绑定 127.0.0.1 非部署方案。
   降级路线（已论证）：Sites 无 Python 重依赖 → 云 ASR + 预计算嵌入 + 云端函数；存储不足 → 外部对象存储。
4. **人工视觉复核**：桌面 + 手机各一次，控制台 0 报错截图留证（验收报告遗留项）。
5. **真机录音测试**：至少 Android Chrome + iOS Safari 各一次完整问答。
6. **演示脚本定稿**（按最新口径）：选论文→播放→跳段→提问"核心方法"→展示文字回答→提问不可回答问题展示拒答→继续播放→切换第二篇论文。
7. **冻结版本**：打 git tag，记录已知限制（上传 PDF 不在本期范围、预置两篇论文、互动无语音）。
8. **作品帖**：链接 + 演示视频/GIF + 技术架构图 + 实测数据表。

## 4. 已知限制（提交时如实声明）

- 论文为预置两篇（Docling 技术报告 / DBDA 故障诊断），本期不支持在线上传解析。
- 互动回答为文字（产品决策：避免 TTS 等待），播客本体为双音色语音。
- 学习目标选择未实现（任务书产品定义项，本期裁剪）。
- 公开 API 不返回论文原文（内容保护决策），证据仅服务端用于约束回答。
- 移动端真机录音兼容性待验证。
