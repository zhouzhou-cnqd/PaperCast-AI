# PaperCast AI 公网演示脚本（比赛版）

> 建议时长：4 分钟。只演示真实公网功能，不把本地语音/Qdrant 指标说成线上实现。

## 演示前 5 分钟

1. 打开 https://papercast-ai-koyte7vo1mh.qoder.zone，确认显示 10 篇论文和文字输入框。
2. 打开「S1 部署自检」，运行一次；确认边缘函数、论文数据、音频 Range 和论文问答通过。
3. 回到「功能演示」，刷新页面，保留 3 次深度额度。
4. 试听 Docling 与 TimesNet；调好系统音量。
5. 关闭会弹通知的应用，浏览器缩放保持 100%。

## 1. 开场（25 秒）

“科研论文很长，但学生的连续阅读时间很碎。PaperCast AI 把英文论文变成可以通勤收听的双角色中文播客，并允许用户随时基于论文内容提问。”

操作：展示 10 篇论文下拉列表、章节栏、播放器、问答区和会话记录。

## 2. 播放与章节联动（40 秒）

1. 选择「Docling 技术报告」。
2. 点击播放，展示双角色播客和动态音浪。
3. 点击左侧不同章节，展示播放器按段跳转。
4. 拖动进度条，说明音频支持 HTTP Range，不需要完整下载后才能播放。

讲解：“播客在离线阶段由 Docling 解析、DeepSeek 生成证据约束脚本，再由双音色 TTS 生成。线上只托管已授权的预生成内容，所以打开快、播放稳定。”

## 3. 快速问答（45 秒）

1. 保持「快速」模式。
2. 输入：**Docling 如何转换 PDF？**
3. 展示短回答、当前问题和右侧历史记录。
4. 点击继续播放，展示恢复到提问前的位置。

讲解：“快速模式直接检索节目内容，适合事实型问题，不消耗深度额度。”

## 4. 深度问答（70 秒）

1. 切换到「TimesNet 时间序列分析」。
2. 点击「深度 · 3」。
3. 输入：**TimesNet 为什么要把一维时间序列变成二维张量？请结合周期内和周期间变化解释，并说明实验依据与局限。**
4. 展示结构化长回答和深度额度从 3 变为 2。

讲解：“函数端检索该论文完整 Docling 解析文本，最多取 10 条候选证据，再让 DeepSeek只根据这些内容回答。完整语料共有 12,758 个文本块，密钥和原文都不会进入浏览器。每位访客最多 3 次深度问答，避免公开额度被刷。”

## 5. 拒答与论文隔离（35 秒）

1. 切回快速模式。
2. 输入：**这篇论文如何用于火星农业？**
3. 展示“论文未提供”类回答。

讲解：“检索始终限定在当前选中的论文；证据不足时明确拒答，不把另一篇论文或常识拼进来。”

## 6. 收尾（25 秒）

“比赛版已经上线 10 篇、183 段播客。Deno 函数测试 9/9，通过完整文本检索的旧 10 问评测为 10/10。完整本地原版还包含 faster-whisper、Qdrant Hybrid 和语音问答，公网则选择纯文字输入，优先保证手机和桌面都能稳定完成核心流程。”

展示 GitHub 仓库与架构图，然后结束。

## 应急预案

| 现场问题 | 处理 |
|---|---|
| DeepSeek 响应慢或额度耗尽 | 切回快速模式，核心播放和问答仍可演示 |
| 网络较差 | 先演示已缓冲音频；随后播放预录的完整公网流程视频 |
| 固定问题未命中 | 使用 Docling 的“如何转换 PDF”或 TimesNet 的二维张量问题 |
| 页面状态异常 | 刷新，运行 S1 自检定位；不要切换到本地录音版 |
| 手机布局拥挤 | 竖屏刷新并保持浏览器缩放默认值；必要时用桌面完成主演示 |

## 需如实说明

- 当前不支持网页上传 PDF，是 10 篇预置内容库。
- 公网只支持文字提问；语音输入属于 GitHub 中保留的本地原版能力。
- 深度回答依赖 DeepSeek，每位访客最多 3 次。
- 互动回答为文字，播客本体为音频。
