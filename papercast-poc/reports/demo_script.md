# PaperCast AI 公网演示脚本（比赛版）

> 建议时长：4 分钟。只演示真实公网功能，明确区分公网链路与本地研究基线。

## 演示前 5 分钟

1. 打开 https://papercast-ai-koyte7vo1mh.qoder.zone，确认显示 10 篇论文、文字输入框和可选录音入口。
2. 打开「S1 部署自检」运行一次，确认边缘函数、论文数据、音频 Range 和论文问答通过。
3. 回到「功能演示」并刷新页面。
4. 试听 Docling 与 TimesNet，调好系统音量。
5. 用文字预问一次“Docling 如何转换 PDF？”，确认 DeepSeek 正常；录音只作为可选展示。
6. 关闭会弹通知的应用，浏览器缩放保持 100%。

## 1. 开场（30 秒）

“科研论文很长，但注意力容易分散的学习者很难持续面对密集文本。PaperCast AI 把英文论文变成可以通勤收听的双角色中文播客，并允许用户听到哪里、问到哪里。它不是替代论文，而是降低开始阅读和维持注意力的门槛。”

操作：展示 10 篇论文下拉列表、章节栏、播放器、论文问答区和会话记录。

## 2. 播放与章节联动（45 秒）

1. 选择「Docling 技术报告」。
2. 点击播放，展示双角色播客和动态音浪。
3. 点击左侧不同章节，展示播放器按段跳转。
4. 拖动进度条，说明音频支持 HTTP Range，不需要完整下载后才能播放。

讲解：“播客在离线阶段由 Docling 解析、DeepSeek 生成证据约束脚本，再由双音色 TTS 生成。重任务提前完成，线上打开快、播放稳定。”

## 3. 证据约束问答与恢复播放（75 秒）

1. 播放进行到任意位置后暂停。
2. 输入：**Docling 如何转换 PDF？它保留了哪些结构信息？**
3. 点击“提问”，展示结构化回答、当前问题和右侧会话记录。
4. 点击“继续播放”，展示播放器回到提问前的位置。

讲解：“公网不再提供容易答偏的关键词快速模式。Qoder Function 会在当前论文的完整 Docling 解析文本中选择最多 10 条候选证据，再让 DeepSeek 只依据这些内容回答。10 篇论文共有 12,758 个文本块，密钥和原文都不会进入浏览器；应用内不限制问答次数。”

## 4. 可选语音入口（30 秒）

1. 点击“开始录音”，说：**这篇论文的核心贡献是什么？**
2. 再次点击结束录音。
3. 展示通义千问把语音转成输入框中的可编辑文字。
4. 不必再次提交长回答，说明文字输入始终可作为稳定入口。

讲解：“语音只是降低输入门槛，不是单点依赖；识别结果先变成文字，让用户确认后再提问。”

## 5. 论文隔离与拒答（35 秒）

1. 切换到「TimesNet 时间序列分析」。
2. 输入：**这篇论文如何用于火星农业？**
3. 展示“论文未提供”或“我不确定”类回答。

讲解：“检索始终限定在当前论文；证据不足时明确拒答，不把另一篇论文或外部常识拼进来。模型返回后还会经过代码级 evidence ID 校验。”

## 6. 收尾（25 秒）

“比赛版已经上线 10 篇、183 段、约 45 分钟的双角色播客。Deno 函数测试 10/10，完整文本检索旧 10 问回归为 10/10。本地原版还保留 Docling、Qdrant Hybrid、faster-whisper 与 TTS 的完整流水线，公网则针对移动端和边缘部署做了稳定化取舍。”

展示 GitHub 仓库、架构图与 Hack4Good 定位，然后结束。

## 应急预案

| 现场问题 | 处理 |
|---|---|
| DeepSeek 响应慢或外部服务异常 | 先演示播客、章节跳转和历史回答截图，再播放预录的完整问答视频 |
| 麦克风权限或语音识别失败 | 立即使用文字输入；明确说明语音是可选入口 |
| 网络较差 | 先演示已缓冲音频；随后播放预录的完整公网流程视频 |
| 固定问题回答不理想 | 使用已预检的“Docling 如何转换 PDF”或 TimesNet 二维张量问题 |
| 页面状态异常 | 刷新页面并运行 S1 自检定位 |
| 手机布局拥挤 | 竖屏刷新并保持浏览器默认缩放；必要时用桌面完成主演示 |

## 需如实说明

- 当前不支持网页上传 PDF，是 10 篇预置内容库。
- 公网支持文字输入和可选通义千问语音转写，互动回答本身仍为文字。
- 深度回答依赖 DeepSeek；应用内不限次数，但受外部 API 余额、并发和服务状态影响。
- 播客在离线阶段预生成，不是每位访客打开页面后即时生成。
