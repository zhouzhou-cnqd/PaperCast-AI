# PaperCast AI 演示脚本（定稿 V1.0 · 2026-11-22）

> 时长目标：3–5 分钟 · 口径：与当前产品一致（互动纯文字回答、无原文面板、右栏问答历史、深色一屏 UI）
> 数据均为实测值，来源见 `demo_acceptance_2026-11-22.md` 与 `metrics.csv`。

## 0. 演示前准备（提前 10 分钟）

```powershell
# 终端 1：后端（papercast-poc 目录；--no-sync 保护 CUDA torch）
uv run --no-sync python scripts/serve_local.py --port 8000 --warmup --pipeline-dir outputs/pipeline --pipeline-dir outputs/papers/diffusion_bridge_gda_fault_diagnosis

# 终端 2：前端（papercast-site 目录）
npm run dev
```

检查清单：
- [ ] `/api/health` 返回 `retrieval_mode=qdrant_hybrid`、`deepseek_key_set=true`、`asr_loaded=true`（warmup 完成后）
- [ ] 页面「S1 部署自检」标签 → 运行客户端自检 → 全部通过（公网演示时在公网链接上跑）
- [ ] 麦克风权限已允许；试录一句确认 ASR 正常
- [ ] 音量合适，双音色可区分

## 1. 开场（30 秒）

台词要点：论文读不动、通勤时间浪费——PaperCast 把论文变成双人中文播客，听到哪问到哪，AI 导师基于论文证据回答，不编造。

操作：打开页面，展示深色一屏三栏布局（左章节 / 中播放器+问答 / 右问答历史）。

## 2. 播放与章节联动（45 秒）

1. 默认选中「Docling 技术报告」，点击播放。
2. 指出：双音色（主持人/研究员）、音浪可视化随声音律动。
3. 等待播放跨段：**左栏自动滚动并高亮当前段落（深色卡片、大字号）**——"讲到哪，亮到哪"。
4. 点击任意章节卡片跳转，说明时间轴精确到段。

## 3. 核心亮点：按住说话提问（90 秒）

1. 在方法相关段落播放中，点击「开始录音」，说：**"论文采用的核心方法是什么？"**，点击「结束录音」。
2. 等待约 4 秒（实测平均 3.68s，P95 4.0s）：展示转写文本 + 导师文字回答。
3. 台词要点：录音 → faster-whisper ASR → Qdrant 混合检索（多语言向量 + BM25，中文问英文论文）→ DeepSeek 基于证据生成短回答；引用 ID 由服务端校验，检索不到就拒答。
4. 点击「继续播放」：**精确恢复到提问前的秒数**。
5. 指出右栏：本次会话问答历史自动留存（最多 10 条）。

## 4. 不编造演示（40 秒）

1. 再次录音提问一个论文外问题，如：**"这篇论文的作者最喜欢吃什么？"**
2. 展示系统明确回答"论文未提供足够信息"，不硬编。
3. 台词要点：证据约束 + 非法引用剔除 + 无证据拒答三道防线。

## 5. 第二篇论文 + 英文提问（40 秒）

1. 下拉切换到「DBDA 故障诊断」（12 页 IEEE 论文，16 段播客）。
2. 录音提问（英文）：**"What are the three main components of DBDA?"**
3. 展示正确返回 TSDB、目标知识保留、历史感知边界扩展损失（实测通过）。
4. 台词要点：跨论文严格隔离（Qdrant paper_id 过滤），跨语言检索。

## 6. 收尾（20 秒）

数据一句话：20/20 真实语音问答全部 10 秒内完成；检索评测 10/10 命中；16 项后端测试全绿；密钥全部在服务端，前端拿不到论文原文。

## 应急预案

| 故障 | 处置 |
|---|---|
| 后端不可达 | 页面有明确错误提示；切到预先录制的完整演示视频 |
| ASR 误识 | 页面显示转写文本，口头说明并换一个问法重录 |
| Qdrant 超时 | 自动回退关键词检索（回答仍可用），说明降级设计 |
| 现场网络差 | 用本地 localhost 演示（提前开好两个终端） |
| 提问超时 >10s | 说明首次模型加载需预热，演示前已 warmup |
